# ADR-042: The configuration surface is a value, not a file

- **Status:** Accepted
- **Date:** 2026-10-24
- **Deciders:** maintainers
- **Refines:** ADR-004 (four-tier config), ADR-030 (provider protocol),
  ADR-031 (fleet declaration), ADR-036 (schema 2).

## Context

A fleet declaration was a JSON file: `desired = "/nix/store/…-desired.json"`,
generated by `pkgs.writeText` and named in the flake output. The core already
evaluates that output for the provider list (`fleet.rs`, `nix eval …#nod`), so
the file was a **second representation** of data the same evaluation already
held. It also made the declaration an untyped attrset in every flake: a typo in
a provider field surfaced only when the daemon started.

A JSON file is still the right form for a fleet that has no Nix: `.nod.toml`
names a path, a script writes it. The mistake was to make that form the only
one.

## Decision

### 1. `desired` is an explicit source

`DesiredSource` has two variants: an **inline document** and a **path**. A
flake carries the document; a configuration file or `--desired` names a file.
The core parses both through one implementation, so they cannot drift.

### 2. The document lives in the domain

`domain::desired` holds the declaration, its schema (2), and one parser. It is
the contract with every producer — a flake, a TOML file, a script — not a use
case's private type. `derive` stays an expansion in the application layer.

### 3. The fleet is a typed NixOS module

`nixosModules.fleet` declares `services.nod.providers.<name>`: command,
settings, desired, apply, interval, timeout, order, env and policy.
`services.nod.fleet` projects them onto the protocol names in exactly one
place. The flake output is `nod = config.services.nod.fleet`.

The module names no provider, no kind and no fleet; it is structure, and every
fleet supplies values. `nixosModules.nod` remains the **host profile** alias —
two surfaces, two names, no breakage.

### 4. Constructors are split by ownership

`lib.nod` ships the generic document constructors (`resource`, `desired`, with
the duplicate check). Provider-specific constructors stay with the provider's
Nix surface, because the kinds belong to the provider. This fleet keeps the
Authentik constructors in its own tree and consumes the generic ones from the
input.

### 5. Schema 2, accepted both ways

The fleet output declares schema 2. A schema-1 output is still accepted (path
form); an inline declaration in a schema-1 output is refused with the provider's
name. A newer schema is refused by an older daemon instead of being misread.

## Consequences

- One evaluation, one declaration, no artifact on the daemon's path.
- A provider field, an interval or a policy typo fails at evaluation.
- File-backed fleets are unchanged: `desired = "…json"` still parses.
- The rendered `nodDesiredState` remains as an artifact for checks and a manual
  apply; it is derived from the value, not a second source.
- The host profile (`options.nod`) and the fleet declaration (`services.nod`)
  are separate namespaces with separate lifetimes; a reconciler host sets both.

## Alternatives

| Alternative | Why not |
|---|---|
| keep the file as the only form | skips the evaluation the daemon already performs; untyped |
| inline only | breaks every `.nod.toml` and `--desired` user |
| one namespace for host and fleet | conflates a machine's profile with the fleet it manages |
| `nix eval` per provider run | a second evaluation per cycle; the 50 s cost we refused |
| provider-specific kinds in the core module | the core would learn every provider's vocabulary |
